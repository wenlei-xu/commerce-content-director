# Active content-system configuration

Fresh-read exactly one active `system_config` record before creative work. Write `plan/content-system-config-snapshot.json` with the record/config IDs, weights, allowed target durations, raw segment duration, first-frame aspect ratio, fixed first-frame executor `gpt_image_2`, fixed image-model ID `gpt-image-2`, fixed image output `1152x2048`/high/PNG, fixed `omni_portrait` video model key, and input limits.

The snapshot is the authority for target duration, duration-plan capabilities, first-frame aspect ratio, scoring weights, rotation defaults, execution limits, and model input limits for the run. For final video, the normal profile is `video_model=omni_portrait`, 10-second portrait `9:16` Segments, plus any directly supported 8-second, 6-second or 4-second tail model confirmed by the live model catalog. The target runtime must be the smallest supported duration-plan sum that is at least the final TTS duration; it no longer needs to be divisible by 10. Never guess a tail model or fallback duration.

Use `scripts/snapshot_content_system_config.py` to validate and write the snapshot. It must remain read-only against Feishu. Supply `--image-model gpt-image-2`; the first-frame execution preflight must confirm that exact model and the planned routed input count. If there are zero or multiple active records, invalid weights, a non-portrait 9:16 profile, an unavailable/unverified GPT Image 2 route, an unavailable `omni_portrait` model, an unavailable exact 8-second/6-second/4-second tail model when required, or an unreadable input limit, stop. Flow2API's model catalog is consulted for final-video duration capabilities.

Schema resolution is separate from business configuration: `config/base-schema.json` owns mappings; this record owns current limits and capabilities. Update the schema before changing structure, and run the lifecycle script's schema check before resuming operations.
