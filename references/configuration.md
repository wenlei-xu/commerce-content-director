# Active content-system configuration

Fresh-read exactly one active `system_config` record before creative work. Write `plan/content-system-config-snapshot.json` with the record/config IDs, weights, allowed target durations, raw segment duration, first-frame aspect ratio, fixed first-frame executor `gpt_image_2_5`, fixed image-model ID `gpt-image-2.5`, fixed image output `1152x2048`/high/PNG, fixed `omni_portrait` video model key, and input limits.

The snapshot is the authority for target duration, duration-plan capabilities, first-frame aspect ratio, scoring weights, rotation defaults, execution limits, and model input limits for the run. For final video, the duration profile is direct 4-second, 6-second, 8-second and 10-second portrait `9:16` Segments, each mapped to the exact Omni portrait model confirmed by the live model catalog. The target runtime must use the smallest supported duration-plan sum that is at least the final TTS duration, while the actual sequence should also follow ASR timing and visual action boundaries. Never guess a duration model or crop a longer Segment.

Use `scripts/snapshot_content_system_config.py` to validate and write the snapshot. It must remain read-only against Feishu. Supply `--image-model gpt-image-2.5`; the first-frame execution preflight must confirm that exact model and the planned routed input count. If there are zero or multiple active records, invalid weights, a non-portrait 9:16 profile, an unavailable/unverified GPT Image 2.5 route, an unavailable `omni_portrait` model or an unavailable exact 4-second/6-second/8-second/10-second duration model when required, or an unreadable input limit, stop. Flow2API's model catalog is consulted for final-video duration capabilities.

Schema resolution is separate from business configuration: `config/base-schema.json` owns mappings; this record owns current limits and capabilities. Update the schema before changing structure, and run the lifecycle script's schema check before resuming operations.
