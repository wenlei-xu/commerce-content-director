# 原创 UGC 策划与飞书热更新规则

本文件定义原创策划的**固定流程**及飞书原创规则的读取契约。“原创规则”表只保存长期有效的边界和检查项；具体创作思路以已收敛的“内容策划任务”的原创专用字段为准。明确要求从大方向扩散时，创意字段先写入“创意候选”，入选后再映射为任务。

## 1. 职责边界

### 1.1 固定在 Skill 中的规则

以下规则不可由飞书配置覆盖：

- 只依据已确认的产品事实创作，不虚构功效、价格、优惠、安全或平台背书。
- 产品结构、连接关系、唯一装填路径及禁止动作是硬约束；具体路径必须从当前产品记录的 `产品硬事实与禁忌` 读取。底部圆孔装粮仅是相应产品的示例，不得泛化到所有产品。
- 成片时长只能是 20、30 或 40 秒；每个 10 秒 Omni 原始段必须有一张四格、零间距、单格 9:16 的生成分镜图，并通过本 skill 的校验器。按目标时长顺序生成 2、3 或 4 个 10 秒段，不使用旧版 8 秒段裁切流程。
- 先完成飞书记录、附件和人工审核；只有指定记录已“通过”且用户明确点名后才可以生成视频。

### 1.2 放在飞书、允许热更新的规则

“原创规则”表只保存四项：平台合规禁忌、通用表达边界、必须检查项、账号长期定位。具体的目标人群、痛点、卖点、钩子、叙事节奏、证明场景和核心创意，只能由`创意候选`（仅扩散阶段）或`策划模式=原创`的“内容策划任务”（已收敛后）提供。

飞书规则只能收紧或补充固定规则，不能放宽、删除或与其冲突。发生冲突时停止创作，记录冲突并请求人工处理。

## 2. 飞书配置表契约

在“短视频内容创意库 / 内容库”Base 内使用“原创规则”表（`table_id=tblOeAQHZeY9sr0y`）。该表只维护**一条当前配置记录**；直接更新该记录即可。出现零条或多条记录时，停止创作并报告配置异常。

| 字段 | 用途 | 填写规则 |
| --- | --- | --- |
| `平台合规禁忌` | 平台不能触碰的内容 | 禁用的宣称、画面、引导方式和其他平台合规红线；不得与产品硬事实冲突 |
| `通用表达边界` | 所有原创内容共用的表达范围 | 可用语气、禁止夸张方式和事实表述边界；不写具体钩子、卖点组合或剧情 |
| `必须检查项` | 生成前的硬性检查清单 | 每项必须可回答“是/否”；用于 `Agent 自检` |
| `账号长期定位` | 账号长期保持的身份和价值取向 | 只写稳定定位，不写单条视频的创意方向 |

## 3. 热更新读取流程

每次原创策划在产出候选创意之前执行以下步骤。一次运行中使用的规则快照不可中途变更。

1. 读取“原创规则”的唯一当前记录；必须恰好存在一条，且四个字段均非空。
2. 原样使用四个字段作为边界、长期定位和检查清单；不得从该表推导钩子、卖点排序、剧情或具体镜头。
3. 将查询时间、Base/table ID、记录 ID、四个字段的完整内容和内容摘要 hash 写入 `plan/creative-rules-snapshot.md`，并在 `Agent 自检` 中保留记录 ID 与快照 hash。

默认不读取内容库。仅当用户明确要求“避开近期内容”“做差异化”或“参考历史”时，才读取历史内容并在 `plan/library-history.md` 记录相似点。相似只作为提示，不能拒绝、阻断或自动改写一个可用创意；有意复用时记录复用原因即可。内容库无法读取不影响普通原创。原创规则表无法读取、不是唯一记录、任一字段为空，或规则与产品硬事实冲突时，才必须在生成创意前停止。正在审核或已审核的包不因后续热更新而被悄悄改写；修改内容需按原审核流程重新提交。

## 4. 内容母题扩散流程

仅在用户明确要求扩散大方向，或明确点名`内容母题`记录时执行；这不是分镜生成流程。

1. Fresh-read 一条`扩散状态=待扩散`的内容母题。要求`产品`、`平台 / 账号`、`大方向 / 营销目标`、`期望候选数`、`收敛方式`和`优先级`非空；候选数为 3–12 的整数，收敛方式仅为`人工筛选`或`自动 Top 1`。
2. 直接读取产品事实、可选主体资产和原创规则快照；仅在用户要求差异化时读取内容库历史。把产品硬事实、禁忌、合规边界和主体身份约束作为候选淘汰条件。
3. 从钩子、场景、任务/冲突、人物关系、视觉母题和卖点组合上拉开差异，创建恰好 N 条合格`创意候选`。每条候选填写所有原创创意字段、差异化标签、六项 1–5 分评分、算术平均`综合评分`和`评分说明`，关联母题并标为`备选`、`未创建`。
4. `人工筛选`：把母题更新为`候选待确认`并停止。只有人工将一条候选标为`入选`、且写入母题的`入选候选`后，才可在后续明确指令中创建任务。
5. `自动 Top 1`：以综合评分最高者为入选；同分时依序比较产品贴合、证据密度、转化强度。把该候选标为`入选`并写入`入选候选`。
6. 仅从入选候选创建一条`内容策划任务`：候选的七个创意字段逐字段复制；母题的产品、平台/账号、优先级、创作要求和可选主体资产继承；设置`策划模式=原创`并填写`来源创意候选`。回读确认关联后，把候选设为`已创建`、母题设为`已收敛`。

扩散阶段不得创建`内容库`记录、生成分镜或图片、提交视频 Job，或从`备选`/`淘汰`候选创建任务。已创建任务后，按下一节的普通原创流程执行。

## 5. 原创策划流程

1. 先执行主 SKILL 的“Mandatory service preflight”。若 Flow2API 与 Feishu MCP 均不可用，立即停止，不读取产品、任务或规则，不创建本地 package，也不写任何文字分镜。通过预检后，未明确说`复刻`时自动按原创处理。直接在飞书`产品`表按用户给出的产品名称或产品ID检索并读取产品事实、禁忌、默认产品锚点和可选的`产品审核要求`，再读取账号定位和原创规则快照。若存在`产品审核要求`，原样保存并按其中的 `PASS`、`WARN｜人工复核`、`FAIL` 分类执行产品专属审核；空字段使用 skill 的严格默认审核。随后读取对应`策划模式=原创`的内容策划任务及其原创专用字段（含`叙事节奏`）作为创意方向，并 fresh-read `任务状态`、`已生成版本数`、`轮换上限`，再回读该任务在`内容库`中的实际版本数。若任务已归档或实际版本数达到轮换上限（默认 5），先按自动轮换契约归档旧任务并创建一条新的原创任务，再从新任务继续；不得删除旧任务，且必须 fresh-read 确认新任务写入成功后才继续创意生成。若任务使用跨镜头主体，优先读取任务已绑定的`主体资产`，为空或无效时自动从`主体资产库`选择一条状态可用、锚点和身份描述完整的最匹配记录，并在本地 package 与后续内容版本中记录选择结果；不得因任务字段为空而追问或停止，也不得把任务的产品关联当作产品检索入口。普通原创生成默认读取该任务最近的内容版本摘要用于差异化；只把历史相似作为方向选择信息，不把相似本身当作拒绝理由。
2. 私下生成多个候选，从钩子、场景、任务/冲突、人物关系、视觉母题和卖点组合上拉开差异。
3. 淘汰无事实支撑、产品交互不合理、无法以手机视频可信呈现、或违反原创规则边界的候选。历史相似不构成淘汰理由。
4. 从产品贴合、转化强度、证据密度、UGC 真实感、可执行性和合规性评分，选出一个方向；不要求用户在创意方向中选择。内容母题扩散已在上一节处理候选展示与人工筛选，不得在此重新写候选。用户明确要求差异化时，才把历史相似度作为辅助评分项。
5. 完成标题、目标用户与痛点、核心利益、钩子、剧情摘要、商业目标、CTA、完整脚本、镜头摘要、逐镜头提示词、视觉关键词和自检；此阶段只保存本地 run package，不写入内容库。
6. 用 Flow2API MCP 的 Banana Pro（`gemini-3.0-pro-image-portrait`）一次生成每个 10 秒原始段的完整四格分镜图；提示词必须声明每格的起止时间、时长、阅读顺序及 2x2 零间距布局。生成前为每个 segment 建立 `product_asset_plan`：结构/装粮/出粮/清洗镜头强制传入产品细节图，宠物互动/尺度/场景镜头强制传入产品场景图；有 recurring 主体时仍须传入主体锚点与默认产品锚点，并在三张输入图限制下按镜头风险选第三张图，不能默默省略关键资产。提示词必须要求孔径、产品尺度和结构严格匹配路由资产，不得因“清晰展示”而放大孔径。四格时长按叙事需要分配，总计 10 秒。对每个 Job 使用 `flow_wait_job`，`queued`、`submitting`、`active` 均继续等待，只有终态才可判定结果。下载完成后运行校验器，并将每一格与对应细节/场景资产逐格比对。**任何预期分镜图缺失、未通过校验、资产路由缺失或仍未终态时，不得创建或更新内容库记录，也不得上传任何内容库附件。**

## 6. 发布前自检与内容库归档

在 `Agent 自检` 中逐项回答“是/否”：

1. 第一面板是否只使用了已声明的一种钩子？
2. 第二面板结束前是否能理解具体根因？
3. 第三面板结束前是否展示了产品首个有效结果？
4. 第四至第六面板是否分别给出机制、操作、结果三类证据？
5. 每个面板是否新增销售相关信息？
6. 每一项说法是否都由产品事实或可见证据支持，并在 20 秒内完成 CTA？
7. 是否记录了本次使用的飞书规则记录 ID 与快照 hash？

全部预期分镜图均已通过校验和逐格审核后，才可写入内容库记录：`内容标题`、`content_id`、创作模式、`内容策划任务`、平台/账号、时长、产品事实、产品审核要求快照、创意字段、脚本、分镜、提示词、最终分镜图、`内容指纹`、`Agent 自检`、审核状态和审核意见。允许人工复核的 `WARN｜人工复核` 必须保留在质量报告、package 和审核意见中；不得将 WARN 静默改写为 PASS。附件验证和审核流以主 SKILL 的规定为准。
