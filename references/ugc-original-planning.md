# 原创 UGC 策划与飞书热更新规则

本文件定义原创策划的**固定流程**及飞书原创规则的读取契约。“原创规则”表只保存长期有效的边界和检查项；具体创作思路以已收敛的“内容策划任务”的原创专用字段为准。明确要求从大方向扩散时，创意字段先写入“创意候选”，入选集合锁定后再映射为一条或多条任务。

## 1. 职责边界

### 1.1 固定在 Skill 中的规则

以下规则不可由飞书配置覆盖：

- 只依据已确认的产品事实创作，不虚构功效、价格、优惠、安全或平台背书。
- 产品结构、连接关系、唯一交互路径及禁止动作是硬约束；具体内容必须从当前产品记录读取，skill 中不得保留任何产品实例。
- 成片时长、原始分段时长、图板行列数和面板比例由活动内容系统配置与当前模型目录共同决定。每块图板必须通过带配置快照的校验器。
- 先完成飞书记录、附件和人工审核；只有指定记录已“通过”且用户明确点名后才可以生成视频。

### 1.2 放在飞书、允许热更新的规则

“原创规则”表只保存四项：平台合规禁忌、通用表达边界、必须检查项、账号长期定位。具体的目标人群、痛点、卖点、钩子、叙事节奏、证明场景和核心创意，只能由`创意候选`（仅扩散阶段）或`策划模式=原创`的“内容策划任务”（已收敛后）提供。

飞书规则只能收紧或补充固定规则，不能放宽、删除或与其冲突。发生冲突时停止创作，记录冲突并请求人工处理。

## 2. 飞书配置表契约

通过 `config/base-schema.json` 的 `original_rules` 映射读取原创规则表。该表只维护**一条当前配置记录**；直接更新该记录即可。出现零条或多条记录时，停止创作并报告配置异常。

| 字段 | 用途 | 填写规则 |
| --- | --- | --- |
| `平台合规禁忌` | 平台不能触碰的内容 | 禁用的宣称、画面、引导方式和其他平台合规红线；不得与产品硬事实冲突 |
| `通用表达边界` | 所有原创内容共用的表达范围 | 可用语气、禁止夸张方式和事实表述边界；不写具体钩子、卖点组合或剧情 |
| `必须检查项` | 生成前的硬性检查清单 | 每项必须可回答“是/否”；用于 `Agent 自检` |
| `账号长期定位` | 账号长期保持的身份和价值取向 | 只写稳定定位，不写单条视频的创意方向 |

## 3. 热更新读取流程

每次原创策划在产出候选创意之前执行以下步骤。一次运行中使用的规则快照不可中途变更。

1. 读取“原创规则”的唯一当前记录；必须恰好存在一条，且四个字段均非空。
2. 原样使用四个字段作为边界、长期定位和检查清单；不得从该表推导钩子、卖点排序、剧情或具体镜头。
3. 将查询时间、Base/table ID、记录 ID、四个字段的完整内容和内容摘要 hash 写入 `plan/creative-rules-snapshot.md`，并在 `Agent 自检` 中保留记录 ID 与快照 hash。

默认不读取内容库。仅当用户明确要求“避开近期内容”“做差异化”或“参考历史”时，才读取历史内容并在 `plan/library-history.md` 记录相似点。相似只作为提示，不能拒绝、阻断或自动改写一个可用创意；有意复用时记录复用原因即可。内容库无法读取不影响普通原创。原创规则表无法读取、不是唯一记录、任一字段为空，或规则与产品硬事实冲突时，才必须在生成创意前停止。正在审核或已审核的包不因后续热更新而被悄悄改写；修改内容需按原审核流程重新提交。

## 4. 内容母题扩散流程

仅在用户明确要求扩散大方向，或明确点名`内容母题`记录时执行；这不是分镜生成流程。

1. Fresh-read 一条`流程状态=待扩散`的内容母题。要求产品、平台/账号、主体资产池、母题描述、商业目标、视频时长、期望候选数和收敛方式非空；候选数为 3–12 的整数，收敛方式仅为`人工选择`或`自动 Top N`。使用`自动 Top N`时，`自动入选数`必须为 1–期望候选数。
2. 直接读取产品事实、可选主体资产和原创规则快照；默认不读取内容库历史，只有用户明确要求避开近期内容、做差异化或参考历史时才读取，并按 `plan/library-history.md` 记录查询和相似性说明。把产品硬事实、禁忌、合规边界和主体身份约束作为候选淘汰条件。
3. 从钩子、场景、任务/冲突、人物关系、视觉母题、声音和卖点组合上拉开差异；内部生成 2–3N 条粗方向，完成硬门槛、相似聚类和组合配额后，创建恰好 N 条合格`创意候选`。每条候选填写目标人群、痛点、核心卖点、内容形式、核心创意、钩子、叙事结构、主要证明动作和互动 / CTA；再写合并后的`准入结果`与`淘汰原因`，对 PASS 候选填写三项加权评分，公式字段自动计算`综合评分`。
4. `人工选择`：把母题更新为`候选待确认`并停止。人工可将一条或多条候选标为`候选状态=入选`，包括全部候选；确认后把母题更新为`选择已锁定`，才可进入后续任务创建步骤。
5. `自动 Top N`：按综合评分选择前`自动入选数`条；同分时依序比较产品贴合、证据密度、转化强度。把这些候选标为`入选`，把母题更新为`选择已锁定`。
6. 从每条锁定的入选候选创建一条独立的`内容策划任务`：候选字段逐字段复制；母题的产品、平台/账号、主体资产池中的对应主体、视频时长和`特殊要求`继承。使用母题记录 ID 加候选记录 ID 作为幂等键，设置`策划模式=原创`并填写`来源创意候选`。回读确认每条`落地内容策划任务`关联后，只有全部入选候选都成功关联任务后，才把母题设为`已收敛`；若部分任务创建失败，保留成功任务并把母题设为`处理失败`。

扩散阶段不得创建`内容库`记录、生成分镜或图片、提交视频 Job，或从`备选`/`淘汰`候选创建任务。已创建任务后，按下一节的普通原创流程执行。

## 5. 原创策划流程

1. 先执行主 SKILL 的“Mandatory service preflight”。若 Flow2API 与 Feishu MCP 均不可用，立即停止，不读取产品、任务或规则，不创建本地 package，也不写任何文字分镜。通过预检后，先读取活动内容系统配置并写出 `plan/content-system-config-snapshot.json`；未明确说`复刻`时自动按原创处理。直接在飞书产品表按用户给出的名称或 ID 检索当前产品事实、禁忌、默认锚点和产品审核要求，再读取账号定位和原创规则快照。随后读取原创任务及其创意字段、生命周期字段和目标时长。任务上限为空时使用活动配置默认值；目标时长必须同时满足活动配置与模型目录。自动版本数是轮换唯一依据；旧版本计数字段只作为历史快照。若达到上限，按自动轮换契约创建新任务后再继续；不得删除旧版本。若任务使用跨镜头主体，优先读取已绑定主体资产，为空或无效时从主体资产库选择可用匹配记录，并在本地 package 与后续内容版本中记录选择结果。普通原创生成默认不读取最近内容；只有用户明确要求避开近期内容、做差异化或参考历史时才读取内容库。
2. 私下生成多个候选，从钩子、场景、任务/冲突、人物关系、视觉母题和卖点组合上拉开差异。
3. 淘汰无事实支撑、产品交互不合理、无法以手机视频可信呈现、或违反原创规则边界的候选。历史相似不构成淘汰理由。
4. 从产品贴合、转化强度、证据密度、UGC 真实感、可执行性和合规性评分，选出一个方向；不要求用户在创意方向中选择。内容母题扩散已在上一节处理候选展示与人工筛选，不得在此重新写候选。用户明确要求差异化时，才把历史相似度作为辅助评分项。
5. 完成标题、目标用户与痛点、核心利益、钩子、剧情摘要、商业目标、CTA、完整脚本、镜头摘要、逐镜头提示词、视觉关键词和自检；此阶段只保存本地 run package，不写入内容库。
6. 用当前可用的图像模型一次生成每个原始段的完整配置图板；提示词必须声明配置的每格起止时间、时长、阅读顺序及零间距布局。生成前为每个 segment 建立 `product_asset_plan`：结构敏感镜头传入产品细节图，真实使用、互动或尺度镜头传入产品场景图；有 recurring 主体时仍须传入主体锚点与默认产品锚点。按当前模型目录的输入限制路由全部必要资产；超出上限时拆分到合适的 Job 或在生成前停止并记录资产冲突。提示词必须要求结构、尺度和交互严格匹配路由资产。每格时长按叙事需要分配，总计为配置原始段时长。下载完成后用 `--profile plan/content-system-config-snapshot.json` 运行校验器，并将每一格与对应证据资产逐格比对。**任何预期分镜图缺失、未通过校验、资产路由缺失或仍未终态时，不得创建或更新内容库记录，也不得上传任何内容库附件。**

## 6. 发布前自检与内容库归档

在 `Agent 自检` 中逐项回答“是/否”：

1. 第一面板是否只使用了已声明的一种钩子？
2. 第二面板结束前是否能理解具体根因？
3. 第三面板结束前是否展示了产品首个有效结果？
4. 第四至第六面板是否分别给出机制、操作、结果三类证据？
5. 每个面板是否新增销售相关信息？
6. 每一项说法是否都由产品事实或可见证据支持，并在 20 秒内完成 CTA？
7. 是否在本地 package 的 `plan/creative-rules-snapshot.md` 中记录了本次使用的飞书规则记录 ID 与快照 hash（不写入已废弃的内容库字段）？

全部预期分镜图均已通过校验和逐格审核后，才可写入内容库记录：`内容标题`、`content_id`、创作模式、`内容策划任务`、平台/账号、时长、产品事实、创意字段、脚本、分镜、提示词、最终分镜图、`Agent 自检`、审核状态和审核意见。`产品审核要求快照`、`内容指纹`、`原创规则记录 ID/hash` 均为已废弃的内容库字段，不得创建或强制写入；详细产品审核证据保留在本地 `quality-report.md` 和 package，规则记录 ID/hash 保留在 `plan/creative-rules-snapshot.md`。允许人工复核的 `WARN｜人工复核` 必须保留在质量报告、package 和审核意见中；不得将 WARN 静默改写为 PASS。附件验证和审核流以主 SKILL 的规定为准。
