# 四表自动归档与筛选

## 归档位置

归档仍留在原来的飞书表中，不移动、不复制、不删除。脚本只写现有状态字段为 `已归档`，并写入 `归档时间`、`归档原因`。默认视图只显示活跃记录；另建“归档”视图筛选 `已归档`，需要历史时切换视图即可。

这套规则只覆盖会裂变的四张表：`内容母题`、`创意候选`、`内容策划任务`、`内容库`。`产品`、`主体资产库`、`最终成片`不由脚本归档；最终成片只作为内容版本是否已被有效接收的只读证据。

## 字段约定

四表统一使用以下生命周期字段（表中已有同名字段时复用）：

| 表 | 状态字段 | 自动补充字段 |
| --- | --- | --- |
| 内容母题 | `记录状态`：活跃 / 已归档 / 待清理 | `归档时间`、`归档原因`、`归档保护` |
| 创意候选 | `记录状态`：活跃 / 已归档 / 待清理 | `归档时间`、`归档原因`、`归档保护` |
| 内容策划任务 | `任务状态`：活跃 / 已归档 | `归档时间`、`归档原因`、`归档保护` |
| 内容库 | `版本状态`：活跃 / 已归档 | `归档时间`、`归档原因`、`归档保护` |

`归档保护`为真时，脚本只报告，不写入。它是临时保留记录的人工闸门。

## 自动判定规则

脚本按 `内容库 → 内容策划任务 → 创意候选 → 内容母题` 的顺序执行：

1. `内容库`：审核为“拒绝”且同一任务已有更新版本，或该版本已被“有效”的最终成片接收，才建议归档。待审核、断链、无替代版本的记录不会自动归档。
2. `内容策划任务`：只在自动反向关联计数达到 `轮换上限`，并且存在通过 `轮换来源任务` 明确指向它的活跃替代任务时归档。达到上限但没有替代任务时只报告待处理，不替用户创造新方向。
3. `创意候选`：候选状态为“淘汰”，或状态为“入选”且已经关联落地任务时归档；来源母题已归档且仍为“备选”的候选也可随之归档。
4. `内容母题`：流程已收敛/处理失败，且所有已关联候选都已淘汰或已落地时归档。没有子候选的母题不会被脚本猜测归档。

## 执行方式

```text
python scripts/lifecycle_sweeper.py --check-schema --json
python scripts/lifecycle_sweeper.py --json                 # 只读 dry-run
python scripts/lifecycle_sweeper.py --apply --json         # 明确写入归档状态
```

每次 apply 都会逐条写入并记录结果；单条失败不会掩盖其他记录。脚本没有删除接口，也不会修复内容版本关联。关联修复仍需单独审计后由人工授权。
