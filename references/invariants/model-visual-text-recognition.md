# 模型视觉文字识别契约

视频中的字幕、标题、标签、价格、CTA、品牌字样及其他屏幕文字，统一由当前模型直接查看视频帧或接触表后识别。可以使用本地脚本抽帧、裁图和制作接触表，但不得安装、调用或依赖 PaddleOCR、Tesseract、EasyOCR、系统 OCR、浏览器 OCR、云端 OCR API 或其他独立文字识别引擎。

## 取证方式

1. 先按工作流要求抽取逐秒帧和动态边界补帧，再把帧作为图像证据交给模型查看。
2. 接触表只用于覆盖扫描和定位文字变化。文字过小、模糊、遮挡或需要逐字确认时，模型必须继续查看对应的原始分辨率单帧或局部裁图。
3. 每条识别结果必须关联时间码或时间范围，并区分：
   - `原文`：模型可以直接确认的可见文字；
   - `无`：该范围确实没有承担叙事作用的屏幕文字；
   - `[无法确认]`：存在疑似文字，但清晰度不足以可靠转写。
4. 不得根据视频标题、作者文案、ASR、上下文或相邻帧补写看不清的屏幕文字。ASR 与屏幕文字可以互相校验，但不能互相冒充证据。
5. 对字幕样式、位置、颜色、强调方式和出现节奏的判断也必须来自模型可见的帧证据；无法确认时降低置信度并记录缺口。

## 字段兼容

飞书字段 `OCR覆盖情况` 是保留的历史字段名，不代表允许调用 OCR 工具。该字段必须记录模型视觉检查的覆盖范围、使用的帧证据、已确认文字范围、无文字范围和无法确认范围；推荐以 `模型视觉识别：` 开头。

`逐秒帧分析` 中若保留 `OCR原文` 这一历史键，其值也只能来自模型视觉识别。新建本地中间结构时优先使用 `屏幕文字原文` 或 `模型视觉文字证据`。

## 失败与停止

若模型无法可靠查看原始帧、关键文字持续不可辨认，或现有抽帧不足以覆盖文字变化，先补帧或提供原图。仍无法确认时保留 `[无法确认]` 和低置信度，不得为了填满字段而调用其他 OCR 引擎或猜测文本。
