# 批次创意差异契约

批量生产的每条脚本必须有独立的内容解法。差异看叙事和画面行为，不看产品名称、颜色、外形或同义动作词。

## 检查对象

对同一批待生产脚本，比较以下结构：

- Hook 的问题或观看承诺；
- Beat 的功能顺序；
- 主要动作模式和产品证明方式；
- 结果或 CTA 前的收束方式。

若两条脚本只替换产品名、产品结构、材质或少量动作词，而上述结构相同，则视为创意重复。脚本不得进入首帧生产，除非用户明确要求复用同一创意结构，并在批次清单中记录原因。

## 选择规则

批次规划时，先为每条脚本确定一个主创意标识和一个主要画面解法。主画面解法可以来自可用互动模板，也可以直接根据产品的 `交互能力` 设计；模板库没有对应记录不构成停止条件。

产品硬事实、`交互能力` 和 `关键结构锁` 仍然决定动作能否执行。创意差异不能通过虚构接触方式、产品功能或证明结果获得。

## 检查命令

脚本批次完成、首帧生成开始前运行：

```powershell
python scripts/validate_batch_creativity.py <script-1.md> <script-2.md> ... --json
```

检查器只负责发现批次内重复；单条脚本的产品事实、时间轴和字段完整性仍由 Markdown 创作稿校验器负责。用户明确要求同一创意时，可使用 `--allow-shared-structure --reason <reason>`，并保留该例外证据。
