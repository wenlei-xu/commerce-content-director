# 创作稿契约

创作稿是人和 Agent 共同审阅、修改的内容中心，使用 Markdown。

创作稿只回答：这段口播对应什么画面，画面中谁做什么，状态如何进入和结束。它可以在执行前逐段补齐，但不能把同一个动作拆成 Beat、动作导演说明和互动计划多份副本。

## 推荐格式

```markdown
# 产品视频

产品：...
主体：...
场景：...
口播：...
TTS：...
ASR：...

## S01｜0–6 秒

对应口播：...

画面：
狗狗已经把玩具叼在嘴里，主人伸手想拿回，狗狗往后退一步，
把玩具护在身下。

衔接：
下一段从狗狗仍然拥有玩具开始。

必须看清：
产品真实接触位置和狗狗的反应。

生成结果：
首帧：待生成
视频：待生成
```

`S01` 是生成段落；`Beat` 只在有复杂故事组织需求时作为可选标签。一个 Beat 可以覆盖多个生成段落，一个段落也可以不挂 Beat。段落数量、时间和内容以真实 ASR 与动作完整性为依据，不使用所有产品共享的预置动作链。

## 内容所有权

- 口播区域拥有用户锁定的口播原文。
- 每个段落的 `对应口播` 只建立引用，不复制并改写台词。
- `画面` 是动作的唯一内容描述。需要动作时直接写“谁做什么、发生什么变化”。
- `衔接` 只写下一段必须继承的状态。
- `必须看清` 只写确实影响产品理解或验收的事项；没有就省略。
- 模板名称、机位参数和 Prompt 不属于创作稿的必填内容。

产品事实、主体身份、场景资产和结构锁仍从当前库读取，不由创作稿覆盖。创作稿可以引用事实或说明场景使用，但不能制造未确认的功能和效果。

## 写作顺序

1. 先锁定或写出口播。
2. 生成完整 TTS 并 ASR，记录真实时间。
3. 按口播含义和可完成的动作建立段落。
4. Agent 为每段写清楚画面事件，并检查前后状态。
5. 进入生成阶段时，才为当前段落写首帧或视频 Prompt。

口播已经明确时，画面可以自由创作，但必须让口播所指的产品、动作或结果在合理时间内可见。口播不指向某个可见证据时，不强制安排一段产品演示。

## 执行适配

执行前，Agent 为需要生成的段落保存独立 Prompt：
`prompts/<segment_id>.<stage>.prompt.md`，其中 `stage` 为
`first_frame_image` 或 `final_video`。随后运行
`scripts/prepare_execution.py`，把创作稿、Prompt、段落时间和版本摘要组装成
执行计划；再由 `scripts/compile_generation_prompts.py` 只补充模型、尺寸、时长和音频等技术约束。
编译器不得重写画面事件，也不得从模板库补动作。

## 修订规则

改变“发生什么”时修改创作稿画面，并令受影响的执行记录过期。改变摄影表达时可以只修改执行记录，但不能让最终 Prompt 与画面描述产生语义冲突。

每次锁定保存 `workbook_revision`。执行记录引用它和段落 ID；创作稿修改后，工具必须拒绝直接提交引用旧修订的请求。未受影响段落可以按影响范围复用已有结果。
