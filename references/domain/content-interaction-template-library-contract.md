# 内容互动模板库契约

`内容互动模板库`是飞书中的跨 SKU 可检索知识表。它沉淀可复用的宠物、人和产品互动节奏，不记录某个 SKU 的专属玩法，也不拥有产品事实、脚本、首帧审批或最终成片。

产品硬事实与`交互限制`是产品能否参与互动的唯一权威。模板只记录可复用的内容行为，不替产品声明能力，也不自动判断产品兼容性。

## 模板字段

| 字段 | 作用 |
| --- | --- |
| `互动模板` | 稳定、跨 SKU 的模式名，例如“追逐叼回”“引逗够取” |
| `内容功能` | `兴趣`、`互动`、`情绪`、`节奏`、`证明`、`转场`或`CTA`；同一模板可支持多个功能 |
| `行为流程` | 谁先动、谁响应、如何结束的可见行为链；同时写清视角、方向、幅度/距离、速度/节奏和必要的重复次数 |
| `可视验收点` | 观众必须看清的行动或反应；要求可被剪辑复核，不能只写“有互动” |
| `模板状态` | 仅 `可用` 模板可进入脚本 |

## 读取与组合规则

1. 新鲜读取当前产品，确认产品状态为 `可用`，并取得其产品硬事实与`交互限制`。
2. 运行 `python scripts/query_content_interaction_templates.py --product-record-id <record_id>`，只使用 `模板状态=可用` 的模板。
3. 模板不自动证明产品兼容。若真实接触点、结构、受力方向或禁忌与模板流程冲突，停止并改写模板、产品限制或本次创意；不得按类别常识补全。
4. 在本次 `structured_script.interaction_plans` 写入模板记录、内容功能和场景化执行。它属于脚本，不回写模板时间线。
5. `兴趣`、`互动`、`情绪`、`节奏`和`转场`可以不关联卖点，只能描述可见行为、参与和反应；它们不得导出功效或机制文案。只有`证明`计划可关联已确认的产品价值。
6. 没有符合条件的模板时，停止并请求新增/修订模板或确认产品能力；不得发明互动。

## 写入边界

模板库的维护是独立知识库变更，更新后必须回读。脚本生产只读模板库并在产品事实层做兼容性检查。只有出现真正跨 SKU 可复用的新行为节奏时，才新增互动模板。

旧 `产品动作库` 不自动转换为模板：其中的“产品 + 动作”行必须由人工拆分为产品能力与通用行为流程。迁移期间的旧行不属于可用模板，不能进入新脚本。
