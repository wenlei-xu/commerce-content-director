# Workflow: 句式模板库

句式模板库服务原创、轻改和复刻脚本的语言层；它不决定镜头结构，也不替代脚本。AI 负责学习与提案，人工只做审核。

先读 [模型视觉文字识别契约](../invariants/model-visual-text-recognition.md)。屏幕文字候选只能来自模型直接查看帧证据后的识别，不得调用本地或第三方 OCR。

1. 先运行 `python scripts/preflight.py --workflow sentence_pattern_learning --json`。若来源是视频拆解，fresh-read 对应拆解并要求其来源有效、`分析状态=已完成`；无效、待核对或失败的视频不得提炼句式。读取高置信 ASR、模型视觉确认的屏幕文字或已验证脚本，按单一语言任务提炼候选；每条来源视频最多提出 3 条。看不清的屏幕文字不得进入句式候选。
2. 只提炼去掉品牌和具体商品事实后仍能迁移、且只服务一个语言任务的表达。普通事实陈述、孤立参数、无法脱离画面成立的残句和通用程度过高的短语不进入模板库。
3. 为候选填写：`句式名称`、`句式用途`、`语言`、`原句示例`、`模板句式`、`使用说明`，并将`审核状态`设为`待审核`。模板句式把可变部分改成 `[主体]`、`[产品]`、`[结果]`、`[动作]` 等槽位。`使用说明`必须包含 `来源拆解：`、`证据类型：`、`证据时间码：`和`置信度：`，在现有表结构内保留可追溯性。
4. 创建前 fresh-read 全库查重：同一用途、语言和核心句法已存在时，不重复创建；将新来源作为审核依据写入候选或把候选标记为`已合并`。
5. 人工审核只决定：`可用`、`已驳回`或`已合并`，并可写审核意见。AI 不得覆盖人工状态；审核不通过或风格/事实不可靠的句式永远不能进入脚本。
6. 脚本只查询`审核状态=可用`的记录，按用途和目标语言筛出最多 3 条，再填槽自然化。原创脚本可直接使用该库；复刻脚本先保留已选参考的结构，再选择性使用它进行本地化表达。

运行 `python scripts/validate_sentence_pattern.py <candidate.json> --json` 后才创建或更新候选记录。
