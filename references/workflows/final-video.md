# Workflow: final video generation and acceptance

Read authority.md, script-contract.md, script-validation.md, execution-accounting.md, mutation-and-recovery.md, configuration.md, product-contract.md, subject-contract.md, delivery-contract.md, video-prompt-contract.md and [doubao-tts.md](../doubao-tts.md).

Use only after the user names a script whose complete first-frame package has `首帧状态=已通过`.

1. Read `plan/language-lock.json`, run preflight with its `target_spoken_language`, then fresh-read the named script-version record, its `首帧状态`, ordered complete first-frame package, structured script, dialogue manifest, Segment states, English video prompt and accepted-film count. Require `首帧状态=已通过`, a complete first-frame package and one ordered first-frame image per chronological Segment in that version. The task lock, `目标口播语言`, and structured-script runtime value must match. If the user requests a copy rewrite or a time-cropped spoken version, run [dialogue-copy-optimization.md](dialogue-copy-optimization.md) before TTS and use only its confirmed dialogue revision.
2. Allocate every spoken line to exactly one Segment for script, subtitle and evidence ownership. A line cannot cross Segment boundaries, but one continuous TTS take may contain ordered lines from multiple Segments.
3. Select the audio route from the immutable language lock. For Chinese `spoken` or `sparse_spoken`, set `voiceover_provider=doubao_tts_2_0` and `omni_audio_policy=environment_only`. Group the exact approved dialogue into contiguous voiceover blocks: a continuous Chinese narration uses one chronological block and one Doubao TTS 2.0 request; sparse narration may use one take per genuinely separated block. Default Chinese synthesis to `speech_rate=15`. Retain a block manifest with ordered `line_id`, exact text, language, speaker, output hash and non-secret provider report. If a take is slightly longer than its available window, use ASR or silence evidence to shorten only inter-sentence breath gaps, preserving at least 80 ms per boundary; do not trim spoken words, globally time-stretch the voice, raise speech rate automatically, or fall back to line-by-line synthesis. If gap reduction cannot make it fit, stop for an approved copy revision. Never put the API key in run artifacts or Feishu. Thai spoken modes use the approved native-Omni route. `natural_sound_only` skips TTS.
4. Compile Segment prompts from the approved script and its approved first-frame version. Chinese dialogue remains in the dialogue manifest for TTS and subtitles but must not appear in an Omni prompt. Chinese Omni prompts request visuals plus synchronized environmental sounds only, with no speech, narration, singing, humming, or background music. Do not independently rewrite dialogue or CTA.
5. Compile all ready Segment jobs for this script's final-video stage. Before submission, import or upload every reference image through `flow_import_input_asset` or `flow_upload_input_asset`, persist the returned `asset_id` values with the Segment package, and pass only `input_asset_ids` to Flow2API. Never place Base64 reference images inside a batch item. When two or more are ready, submit them through one `flow_submit_batch(kind="video")`, persist the batch-to-Job mapping, and wait through `flow_wait_batch`; use `flow_submit_video` only for one ready or repair Job. This video batch is separate from first-frame generation because human approval of the complete first-frame package is its dependency.
6. For Chinese spoken modes, separate the music stem from the exact approved reference source video with `scripts/separate_reference_bgm.py`. Discard the vocal stem. ASR-check the separated BGM and require a passed `commerce-source-bgm-gate-v1` report with `residual_speech_detected=false`; detected or unverifiable source speech blocks assembly. Never use the reference video's unseparated audio track as the music bed.
7. For Chinese spoken modes, the final voiceover authority is the aligned Doubao track. Assemble exactly three logical tracks: accepted Omni environmental sound, the passed separated reference BGM, and aligned Doubao voiceover. Duck BGM under voiceover; do not replace environmental sound with the reference video's full audio. ASR-check the assembled film against line IDs and the final approved dialogue. Thai follows its selected native-Omni route. For natural sound, perform manual audio review.
8. Build subtitles from the aligned final voiceover timing, never from planned estimates or Omni output. For a complete take, derive each approved line boundary from the final take's real ASR/silence timing while restoring the exact approved text. New timing artifacts retain `line_id`, `start`, `end` and the exact approved `text`; a legacy timing line without `line_id` is accepted only when its text matches exactly one approved dialogue line. `auto_from_final_audio` produces ordinary SRT; `emphasis_from_final_audio` uses the script's exact keyword spans to produce ASS; `none` produces no subtitle track. Never treat independent screen text as subtitles.
9. Assemble only accepted chronological segments, validate duration, portrait geometry, continuity and subtitles. Chinese spoken assembly must use `scripts/assemble_final_video.py --audio-policy chinese_external_tts --voiceover ... --background-music ... --background-music-gate ...`. For emphasized subtitles, visually verify keyword color/scale and confirm the rendered text still exactly matches the approved line in the locked language.
10. After acceptance, create one final-film record linked to the script, attach the playable file and fresh-read it. Increment accepted-film count exactly once.

Stop on exhausted execution limit, any dialogue mismatch, missing first-frame image, failed acceptance or failed remote verification.
