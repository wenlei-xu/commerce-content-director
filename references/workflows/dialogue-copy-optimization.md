# Module: dialogue copy optimization

这是脚本生产和既有画面口播返工时调用的口播模块。它负责把“画面已经发生的动作”转换成自然、有效、可说出口播；不负责生成视频、调用 TTS、上传成片，也不建立第二套脚本事实源。

## Interface

### Locked user copy boundary

如果输入脚本包含用户明确要求直接使用的口播原文，本模块不负责改写。它只能返回逐行时间安排、画面证据和口播时长提示；不得生成润色候选、同义替换、删减、扩写或 CTA 补写。只有用户明确要求“改写”“优化”“压缩”“更口语化”或重新创作时，才允许进入下方候选改写流程。无论是否进入改写流程，最终写回前都必须确认用户锁定的口播原文没有被静默改变。

输入：

- 当前已锁定语言 `plan/language-lock.json`；
- 当前脚本的 `structured_script`；
- Beat / Segment 的画面动作、产品硬事实和主体事实；
- 用户提出的目标，例如“更自然”“更像现场反应”“保留前 15 秒”；
- 若为返工，当前成片的实际保留时间范围和已有口播。

输出：

- 本地 `dialogue-revision-proposal`：逐行保留原 `line_id`，给出问题诊断、候选改写、画面证据、台词功能和时长建议；
- `dialogue-copy-review`：由 `scripts/review_dialogue_copy.py` 生成的非阻断式审核提示报告；
- 用户确认后的唯一改写结果，交还脚本生产流程写回 `structured_script.dialogue`、复盘字段（如有）和字幕强调字段。

## Workflow

1. 先锁定每行台词的画面证据：正在发生什么、宠物或主人有什么反应、产品价值如何被看见。不能先写功能，再强行找画面。
2. 诊断原台词：是否只是复述“拿出、咬住、放下、清洗”等动作；是否像产品说明书；是否有真实反应、利益、证明和自然收尾。
3. 对每个需要修改的 `line_id` 生成 2–3 个完整候选。候选必须保持产品事实、主体身份、叙事顺序和 CTA 意图不变，只改善口语感、现场感和信息密度。
4. 优先使用“反应 → 观察 → 价值/结果”的口语结构。少用书面连接词；每句只承担一个动作或反应；不要为了凑字数添加空泛形容词。
5. 运行 `python scripts/review_dialogue_copy.py <structured_script.json> --out <dialogue-copy-review.json>`，再运行完整的 `scripts/validate_structured_script.py`。审查器只生成非阻断式报告，不改写文字；所有口播质量结果都是改写和复盘建议。结构、时间轴、语言和产品事实等独立校验仍按各自契约执行。
6. 只有用户确认或明确要求采用推荐版后，主脚本流程才把候选写回 `structured_script`，重新渲染审核字段并重新校验。模块本身不直接写 Feishu。
7. TTS、实际语速、ASR 对齐、字幕和混音属于 final-video 流程；口播模块只交付已确认的文字和时间/行号映射。

## Rewrite rules

- 中文每句优先 6–14 字，18 字以内为建议上限；超出只报告，不机械截断。
- 每 2–3 秒画面允许时加入一次自然现场回应，例如“你看”“真的”“它还在研究”“马上就来了”；不能强行插入。
- 产品互动由画面证明，台词说观众关心的结果、感受和使用价值，不重复操作手册。
- 不新增未经产品事实支持的耐久、治疗、绝对效果或比较性承诺。
- 不改变 `line_id`、Segment 所属、CTA 意图或已锁定语言；跨 Segment 的台词必须先重新分配并通过校验。
- 返工裁剪时，只保留完整归属在保留区间内的台词；若最后一句超出边界，先改写或重新安排时间，不截断词语。

## Completion criteria

一个口播改写只有同时满足以下条件才算完成：

- 候选逐行能指向具体画面证据；
- 如填写 `dialogue_quality_gate`，其中的痛点、利益、证明和自然 CTA ID 尽量有真实台词承载；
- 完整脚本校验通过，且字幕强调文本与最终台词逐字一致；
- 用户已确认采用的版本已写回 `structured_script`；
- final-video 阶段再用实际 TTS 音频做 ASR 对齐，不用计划时间替代真实时间。
