# Workflow: storyboard generation and script fidelity

Read authority.md, script-contract.md, script-validation.md, product-contract.md, subject-contract.md, product-execution-contract.md, reference-asset-contract.md, image-prompt-contract.md, [gpt-image-2-execution.md](../gpt-image-2-execution.md) and delivery-contract.md.

Input is one freshly read Feishu script record whose script status is locked and script check status is passed. Its `目标口播语言` and `structured_script.runtime.target_spoken_language` must both match `plan/language-lock.json`. A local script package alone is not sufficient. Read its structured script, accepted product assets, subjects and configuration. Never infer a different creative direction or rewrite the script.

Original and replication modes use the same generation unit. Divide the locked target duration into configured 10-second target production Segments. Each Segment generates complete 2×2 boards containing four 9:16 panels. Generate two self-contained complete storyboard packages, A and B, and write them directly to two script-table records. A human approves one complete script version, never an isolated Segment. Source-video narrative segments, selected evidence frames and reference timestamps do not alter the target production segmentation.

1. Run the workflow-scoped preflight with the locked spoken language and fresh-read the active configuration. Require an approved route that guarantees `gpt-image-2`, then lock `executor=gpt_image_2`, `model=gpt-image-2`, `image_output=1152x2048/high/png`, and `prompt_language=en` into the configuration snapshot and generation plan. Another model, Flow2API image generation, an unverified model binding, or any other executor/prompt-language value is invalid for a storyboard-image request.
2. Compile the generation plan from target-script Beat and target production Segment objects. Record target duration, the fixed production unit, each Segment's contiguous target time range and the two package versions (`A` and `B`). Each storyboard Segment must also declare concise `visual_continuity` plus exactly four static panel keyframes in reading order. Do not create a per-Segment approval record.
3. Map every script Beat to one or more storyboard panels; retain stable Beat, Line and Text IDs in the local package. For each panel, choose one frozen, directly observable instant and record its camera intent, inherited state and minimum human presence. Convert processes such as loading, pouring, opening, turning or dispensing into a decisive single-frame proof moment; never ask one panel to depict the whole process.
4. Prepare approved product, subject and routed reference images with `scripts/prepare_image_inputs.py`. In structure replication, optionally prepare one cleaned `source_scene_reference` per Segment when the user requests source-space reuse; use it only for background geometry, camera, lighting and spatial staging, while target product and subject anchors own identity. Expand both complete packages before execution. For the default 30-second plan, execute all six GPT Image 2 requests through one concurrency-controlled request group with maximum concurrency 5, then retrieve and hash the completed results. Internal retries reuse their idempotency identity and never create a human-facing approval row.
5. Review each complete candidate's product action, state, continuity and timing, then run storyboard fidelity validation. Every Beat, key product action and assigned spoken line must have coverage. Confirm that each panel is an independently readable static moment, carried orientation/state is explicit, human visibility is no greater than planned, and no content crosses panel boundaries. Four panels do not imply four equal time windows; the locked target-script Beat timeline owns their exact timing. Reject the whole board when any panel makes it unusable; never crop or recombine panels.
6. Before image submission, write both script-version records' `分镜状态=生成中` and fresh-read them. Local files are staging artifacts; the script records are the only cross-computer review surface.
7. Validate each complete A/B package across all Segments for subject identity, room/light, product geometry, orientation, food state, action handoff and CTA closure. If a package is not independently coherent, regenerate its conflicting Segment before writeback; never ask the human to manually construct a version from loose boards.
8. Write each complete package directly to its script record with `脚本版本=A/B`, `最终分镜图` attachments ordered by Segment, and `脚本状态=待审核`. The structured script owns Segment order, which is preserved by the remote attachment write order; deterministic attachment names are integrity checks only. No separate storyboard-mapping field is written. Fresh-read both records and verify attachment identity, ordered count and continuity evidence. Machine checks are `视觉预检` only; they do not constitute final visual approval.
9. The human reviews the two complete script records and approves at most one version per source script. Set the selected version to `脚本状态=已锁定` and the other to `脚本状态=未采用`; only the locked version may enter final-video production. Save the evidence to `plan/storyboard-writeback-verification.json` with `run_id`, source script record ID, version record IDs, observed attachment identities, observed statuses and verification time.

Stop before downstream final-video work if any required board, coverage or product-fidelity evidence fails, or if upload, script association, status write, attachment identity/count, or fresh-read verification fails. Resume the same run ID. A GPT Image 2 authentication, model-access, rate-limit, execution or result failure remains a resumable GPT Image 2 failure; never retry it through Flow2API or another image model.
