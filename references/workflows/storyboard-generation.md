# Workflow: storyboard generation and script fidelity

Read authority.md, script-contract.md, script-validation.md, product-contract.md, subject-contract.md, product-execution-contract.md, reference-asset-contract.md, image-prompt-contract.md, [storyboard-candidate-contract.md](../storyboard-candidate-contract.md), [flow2api-image-execution.md](../flow2api-image-execution.md) and delivery-contract.md.

Input is one freshly read Feishu script record whose script status is locked and script check status is passed. Its `目标口播语言` and `structured_script.runtime.target_spoken_language` must both match `plan/language-lock.json`. A local script package alone is not sufficient. Read its structured script, accepted product assets, subjects and configuration. Never infer a different creative direction or rewrite the script.

Original and replication modes use the same acceptance unit. Divide the locked target duration into configured 10-second target production Segments. Each Segment ultimately accepts exactly one complete 2×2 board containing four 9:16 panels. Therefore `accepted board count = target_duration_seconds / raw_segment_seconds`. A Segment may have multiple intentional candidate Jobs; every successful candidate remains a complete board for that same Segment. Source-video narrative segments, selected evidence frames and reference timestamps do not alter the accepted-board count.

1. Run the workflow-scoped preflight with the locked spoken language, fresh-read the active configuration and Flow2API image-model catalog, then lock the exact available model ID into the configuration snapshot and generation plan. Set `executor` to `flow2api_mcp` and `prompt_language` to `en`; no other values are valid for a storyboard-image Job.
2. Compile the generation plan from target-script Beat and target production Segment objects. Record target duration, the fixed production unit, each Segment's contiguous target time range, the exact expected accepted-board count and `candidates_per_segment`. Use the schema default of `2` unless the user explicitly overrides it. Do not create another script merely to obtain more visual options.
3. Map every script Beat to one or more storyboard panels; retain stable Beat, Line and Text IDs in the local package.
4. Prepare approved product, subject and routed reference images with `scripts/prepare_flow_inputs.py`. Expand all Segment attempts before submission. For the default 30-second plan, submit all six candidate Jobs through one `flow_submit_batch(kind="image")`, wait through `flow_wait_batch`, then retrieve each successful result. Increment `attempt` only for an intentional new visual candidate; reuse it for a transport retry. Capacity may split the stage into the fewest possible batches but never into an avoidable loop of single submissions.
5. Review each complete candidate's product action, state, continuity and timing, then run storyboard fidelity validation. Every Beat, key product action and assigned spoken line must have coverage. Four panels do not imply four equal time windows; the locked target-script Beat timeline owns their exact timing. Reject the whole board when any panel makes it unusable; never crop or recombine panels.
6. Before image submission, write the exact script record's `分镜状态=生成中` and fresh-read it. After each candidate passes local validation, publish it with `scripts/storyboard_candidates.py publish` to one linked `分镜候选` record in `候选状态=待选择`. Local files are staging artifacts, never the cross-computer review surface.
7. The human opens the Feishu `人工选片` gallery and checks `是否采用` on exactly one complete board for each Segment. A 30-second script therefore requires three checked records: one for Segment-01, one for Segment-02 and one for Segment-03. The selection never occurs at panel level.
8. Run `scripts/storyboard_candidates.py finalize` for the script. It fresh-reads all linked candidates, rejects missing or duplicate Segment selections, orders the chosen attachments by `Segment 序号`, and writes only those boards to `最终分镜图`. It also writes `分镜状态=待审核`, selected candidate IDs in `分镜审核意见`, and the script-derived `视频提示词` whose control instructions are English and whose spoken payload uses the locked language.
9. After user or authorized acceptance, finalize with approval so that the same script record becomes `分镜状态=已通过`, then fresh-read again. Verify the script record ID, candidate record IDs, attachment token/name/count, status, review notes, and video prompt against the current run. Save the evidence to `plan/storyboard-writeback-verification.json` with `run_id`, `script_record_id`, expected board count, selected candidate IDs, observed attachment identities, observed status, and verification time. Only this verified state completes storyboard production.

Stop before downstream final-video work if any required board, coverage or product-fidelity evidence fails, or if upload, script association, status write, attachment identity/count, or fresh-read verification fails. Resume the same run ID. A Flow2API health, catalog, submission, wait or result failure remains a resumable Flow2API failure; never retry it through GPT Image.
