# Workflow: video first-frame generation and script fidelity

Read authority.md, script-contract.md, script-validation.md, product-contract.md, subject-contract.md, [scene-asset-library-contract.md](../domain/scene-asset-library-contract.md), product-execution-contract.md, reference-asset-contract.md, [first-frame-image-contract.md](../first-frame-image-contract.md), [director-contract.md](../domain/director-contract.md), [first-frame-execution.md](../first-frame-execution.md) and delivery-contract.md.

Input is one freshly read Feishu script record whose script status is locked and script check status is passed. Its `目标口播语言` and `structured_script.runtime.target_spoken_language` must both match `plan/language-lock.json`. A local script package alone is not sufficient. Read its structured script, accepted product assets, subjects and configuration. Never infer a different creative direction or rewrite the script.

Original and replication modes use the same generation unit. Divide the locked target duration into configured 10-second target production Segments. Each Segment generates exactly one 9:16 first-frame image representing the Segment's `t=0` entering state. Generate two self-contained first-frame packages, A and B, and write them directly to two script-table records. A human approves one complete script version, never an isolated Segment. Source-video narrative segments, selected evidence frames and reference timestamps do not alter the target production segmentation.

1. Run the workflow-scoped preflight with the locked spoken language and fresh-read the active configuration. Require an approved route that guarantees `gpt-image-2`, then lock `executor=gpt_image_2`, `model=gpt-image-2`, `image_output=1152x2048/high/png`, and `prompt_language=en` into the configuration snapshot and generation plan. Another model, Flow2API image generation, an unverified model binding, or any other executor/prompt-language value is invalid for a first-frame image request.
2. Compile the generation plan from target-script Beat and target production Segment objects. Record target duration, the fixed production unit, each Segment's contiguous target time range and the two package versions (`A` and `B`). Each first-frame Segment must also declare concise `visual_continuity` plus exactly one `first_frame` decision for the entering state at local `t=0`. Keep the full Beat timeline as timing/continuity metadata; it is not a set of image panels. Do not create a per-Segment approval record.
3. Invoke the `Director` deep module after the script is locked. Give it the locked script projection, product/subject facts, the selected scene asset when a stable environment is needed, selected product actions, resolved replication constraints and the current run's visual goal. It returns one entering-state first-frame decision for each Segment: a directly observable static moment at local `t=0`, camera, composition, performance, continuity and an explicit A/B variant delta. Retain stable Beat, Line and Text IDs in the local package. Do not ask the first frame to depict a process or the whole 10-second action; show only the state from which the Segment begins. The Director may not mutate the locked script, its Beat timeline, dialogue or product facts.
4. Prepare approved product, subject, scene and routed reference images with `scripts/prepare_image_inputs.py`. When a stable environment or phone-capture treatment matters, query `scene_assets` and route one `状态=可用` `scene_anchor`; use it only for background geometry, camera, lighting, usable activity area and lived-in texture. Do not inherit its people, animals, products, text, logos or unsupported actions. In structure replication, optionally prepare one cleaned `source_scene_reference` per Segment when the user requests source-space reuse; use it only for background geometry, camera, lighting and spatial staging, while target product and subject anchors own identity. For every visible product, `product_anchor` is position 1. When routed, `subject_anchor` follows it and `scene_anchor` follows the identity anchors; record every position explicitly in the asset plan. `source_scene_reference` is a separate replication-only role and must not be confused with `scene_anchor`. When the product record declares a fixed integrated visual structure, compile its factual English `product_visual_lock` into every visible-product Segment and route a complete front-view anchor that shows all locked components. Expand both complete packages before execution. Use the project GPT Image 2 image-to-image gateway and submit the complete ready request set in one concurrent group by default; do not impose a fixed five-request cap. If the gateway explicitly signals capacity, rate limiting or timeout, split only the missing requests and retry them with the same ordered inputs and model. Internal retries reuse their idempotency identity and never create a human-facing approval row.
5. Review each complete A/B package's product entering state, continuity and Segment handoff, then run first-frame fidelity validation. The first frame must be an independently readable static moment at local `t=0`; every Beat, key product action and assigned spoken line remains covered by the locked script timeline and downstream video plan, not by extra image panels. Confirm that carried orientation/state is explicit and human visibility is no greater than planned. For an integrated visual lock, verify every visible-product first frame keeps all locked components present, connected at their approved locations and readable from the selected camera. Reject the whole package when any first frame makes the next Segment unusable; never crop, tile or recombine first frames.
6. Before image submission, write both script-version records' `首帧状态=生成中` and fresh-read them. Local files are staging artifacts; the script records are the only cross-computer review surface.
7. Validate each complete A/B package across all Segments for subject identity, room/light, product geometry, orientation, food state, action handoff and CTA closure. If a package is not independently coherent, regenerate its conflicting Segment before writeback; never ask the human to manually construct a version from loose images.
8. Write each complete package with `scripts/publish_first_frame_versions.py`. The writer creates or resumes exactly two script records, each with an actual `来源脚本` relation to the source script record, `脚本版本=A/B`, ordered `最终首帧图` first-frame attachments and `首帧状态=待审核`. The structured script owns Segment order, which is preserved by remote attachment order; deterministic attachment names and local hashes are integrity checks only. No Segment mapping field, candidate record or approval record is written. Fresh-read both records and verify source relation, version, attachment identity, ordered count and continuity evidence. Machine checks are `视觉预检` only; they do not constitute final visual approval.
9. The human may approve either or both complete versions by setting each approved version's `首帧状态=已通过`; every approved version may enter final-video production. Save the evidence to `plan/first-frame-writeback-verification.json` with `run_id`, source script record ID, version record IDs, observed attachment identities, observed statuses and verification time.

Stop before downstream final-video work if any required first frame, coverage or product-fidelity evidence fails, or if upload, script association, status write, attachment identity/count, or fresh-read verification fails. Resume the same run ID. A GPT Image 2 authentication, model-access, rate-limit, execution or result failure remains a resumable GPT Image 2 failure; never retry it through Flow2API or another image model.
