# Workflow: first-frame generation

本流程读取已锁定的 Markdown 创作稿、产品事实、主体/场景素材、语言锁和当前配置。它把创作稿中的生成段落变成首帧执行记录，不重新设计脚本。

## 工作方式

1. 确认创作稿修订、TTS/ASR、段落时间、产品事实和素材都来自当前运行。当前流程只接受 Markdown 创作稿。
2. 依据段落的“画面”和“衔接”写一个能作为视频起点的静态瞬间。首帧只展示进入状态，不展示后续动作链。
3. Agent 直接写当前段落的首帧 Prompt，说明参考素材角色、进入状态、主体姿态、产品放置、镜头关系和必要的连续性约束。不要从 Prompt 模板自动填入默认动作。
4. 通过执行记录保存创作稿修订、段落 ID、素材映射、Prompt、模型、请求和结果，再提交生成工具。
5. 生成后检查产品结构、主体身份、进入状态和下一段衔接。失败只重做受影响段落；创作稿事件发生变化时先修订创作稿。
6. A/B 版本如仍然需要，由 Agent 为整套段落写出两套有具体视觉理由的方案。不能只改变“产品证明”和“反应优先”标签。
7. 生成完整首帧版本后，继续使用现有 Feishu 完整版本审批表面。它记录审批结果，不成为第三份脚本。

## Prompt 规则

Prompt 使用英文控制文本，遵循 [first-frame-image-contract.md](../first-frame-image-contract.md) 的素材、尺寸、模型和输入顺序要求。保留产品锚点、主体锚点、场景锚点和结构锁等执行约束；创意段落由 Agent 从当前稿件写出。

首帧和视频之间的职责是连续的：首帧回答“从什么状态开始”，视频 Prompt 回答“从这里发生什么变化”。视频 Prompt 在首帧通过后再写，不能提前假定生成图一定符合预期。

## 停止条件

缺少可用产品/主体素材、产品事实和画面动作冲突、创作稿修订过期、Prompt 与段落动作不一致、首帧不具备下一段所需的进入状态、素材上传或生成返回失败时，停止对应段落并保存可恢复的执行记录。不要用默认动作、互动模板或旧 Beat 文字补齐缺失创意。
