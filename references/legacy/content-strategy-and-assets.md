# 内容母题、创意候选、内容策划任务与产品

内容策划任务承载已收敛的任务级方向与复刻证据；产品事实和产品素材统一按产品聚合到“产品”表的一条记录中。用户未明确说“复刻”时，默认按原创处理；产品必须直接从“产品”表查找，不要求通过内容策划任务的产品关联来定位。需要从大方向发散时，先在`内容母题`中记录方向，再由 AI 写入多个`创意候选`；只有入选候选才可创建原创内容策划任务，一条入选候选对应一条任务。

## 1. Base 结构

Base、table ID、字段名和状态文本统一位于 [`config/base-schema.json`](../config/base-schema.json)。本文件只说明各表的业务角色，脚本和工作流一律按逻辑键读取映射，禁止复制技术 ID。

| 逻辑表 | 角色 |
| --- | --- |
| 产品 | 一条记录就是一个产品的完整事实、注意事项与图片资产包 |
| 内容系统配置 | 唯一业务控制面：评分、轮换、时长、分段和分镜网格 |
| 内容策划任务 | 唯一的原创与复刻内容入口；用于调整、热更新和版本管理 |
| 内容母题 | 一个大方向的输入和收敛控制；不进入分镜、审核或视频生成 |
| 创意候选 | AI 从母题扩散出的独立创意方向；入选后才可落地为原创任务 |
| 内容库 | 可审核、可生成的具体内容版本 |
| 最终成片 | 仅收录已完整生成、可发布的视频；每条成片关联一个内容版本 |
| 主体资产库 | 可复用的人物、狗、猫等主体身份锚点；一条记录代表一个稳定主体 |

关联方向：`内容母题.产品 → 产品`；`创意候选.内容母题 ↔ 内容母题.创意候选列表`；`内容策划任务.来源创意候选 ↔ 创意候选.落地内容策划任务`；`内容策划任务.产品 → 产品`；`内容库.内容策划任务 → 内容策划任务`；`内容策划任务.内容库版本列表 ↔ 内容库.任务版本归属`；`内容库.产品 → 产品`；`最终成片.内容版本 → 内容库`。复刻用的爆款视频是内容策划任务的直接附件，不另建视频资产记录。一个内容版本必须关联且只能关联一个内容策划任务；两个内容版本关联字段必须指向同一任务。

`内容策划任务.主体资产 → 主体资产库` 与 `内容库.主体资产 → 主体资产库` 用于固定跨分镜的人物/宠物身份。主体资产记录应包含稳定的主体锚点图和身份描述；分镜生成时将其与产品锚点一起作为输入图，不要只在 prompt 里写“同一只狗/同一个人”。任务的 `主体资产` 为空时，不要求人工先绑定：从 `主体资产库` 自动筛选 `状态=可用` 且锚点、身份描述完整的匹配记录；按任务文本中的主体类型/角色、证明场景与默认场景打分，仍并列时按 `record_id` 稳定选择第一条。没有合格记录才停止。

## 2. 产品：唯一产品入口

人工日常只维护一条产品记录，并一次拖入对应附件；不需要为每张图片建记录、起 asset_id 或填写用途。

| 字段 | 用途 |
| --- | --- |
| `产品名称`、`产品ID`、`状态` | 标识与启停；只有 `可用` 产品可用于新内容 |
| `一句话产品定位` | 用一句可核实的话说明产品是什么，供标题和脚本理解产品 |
| `核心卖点` | 已确认、可被内容证明的卖点；一条一行或用编号分隔 |
| `目标人群`、`典型痛点`、`典型使用场景` | 面向谁、解决什么具体问题、在哪些真实场景使用 |
| `可用表达 / 可用宣称` | 可直接使用的已确认话术、材料或体验描述 |
| `禁用表达 / 禁用宣称` | 不能说的功效、价格、安全或夸张话术 |
| `产品硬事实与禁忌` | 产品结构、装粮路径、出粮/漏食路径、其他交互路径和禁止动作；其优先级高于卖点与话术 |
| `生成注意事项` | 容易画错的结构、镜头和交互提醒；这是唯一注意事项来源 |
| `产品审核要求` | 产品专属验收标准，建议按 `PASS`、`WARN｜人工复核`、`FAIL` 分段；只补充产品特有审核边界，不覆盖全局安全、真实性、主体连续性、图板几何或最终成片规则 |
| `默认产品锚点` | 生成时优先使用的确认版产品图 |
| `产品三视图`、`产品细节图`、`产品场景图`、`其他产品素材` | 分类附件，可多选一次上传 |

每次内容创作前，读取所关联产品的全部字段和附件：先锁定硬事实与禁忌，再读取 `产品审核要求`（若为空则使用 skill 的严格默认审核），最后从核心卖点、人群、痛点、场景和可用表达中选择本条内容的论点；禁用表达必须排除。任何本地 `product-routes` 文件、旧资产记录或临时工作目录都不是产品事实来源。若产品记录为空、状态不是 `可用`、缺少默认锚点，或事实与策略冲突，生成前停止。`产品审核要求` 中的 `WARN｜人工复核` 必须原样保存到本地 package、质量报告和飞书审核备注，不得被静默当作 PASS。

### 产品资产路由（生成前强制执行）

读取附件字段后必须按镜头风险把资产实际传入对应的 Flow2API Job，不能只把附件名称写进策划包：

- `默认产品锚点`：产品身份基准，默认随每个相关 Job 传入。
- `产品细节图`：凡是装粮、出粮、清洗、排水、孔径、格栅、连接关系或其他结构敏感镜头，强制传入；提示词必须要求孔形、孔径比例和连接关系严格匹配该图，不得为“看清楚”而放大。
- `产品场景图`：凡是依赖真实使用场景、宠物互动、尺度、摆放或探索动作的镜头，强制传入；它是尺度和交互证据，不是装饰图。
- `其他产品素材`：仅当它确实是一个包含所需结构细节与场景证据的合规资产总览时，才可在对应媒体的输入图限制下替代单独的细节图/场景图。

Flow2API 的 R2I Job 最多 10 张输入图，Omni R2V Job 最多 7 张输入图；旧版非 Omni R2V 以模型目录的 `max_images` 为准。若有 recurring 主体，主体锚点和默认产品锚点均不可省略，其他图片按镜头风险路由：结构镜头优先 `产品细节图`，场景/探索镜头优先 `产品场景图`。同一 Job 同时需要多类产品证据时，优先使用包含所需证据的 `其他产品素材`；超过对应上限时必须拆分到合适的 Job 或在生成前停止并记录资产冲突，不得静默只传默认锚点。每个 Job 的资产角色、字段、文件名、token/hash 和 segment 映射必须写入 `product_asset_plan` 与 `generation-jobs.json`。生成后按路由资产逐格复核产品尺寸、孔径、结构和交互，任何漂移均判 FAIL。

## 3. 内容母题与创意候选

`内容母题`是“给一个大方向，让 AI 展开”的唯一入口；它不是任务、分镜或内容版本。填完一条母题后，明确要求扩散或点名该记录，AI 才会读取它并创建候选。`创意候选`不能直接进入审核、分镜或视频生成。

### 3.1 内容母题字段

内容母题只保留方向输入和收敛控制，不承担审计或规则快照。

| 字段 | 填写规则 |
| --- | --- |
| `母题名称`、`母题ID` | 便于识别的名称和稳定 ID；例如“把狗狗旺盛精力转向互动任务” |
| `产品`、`平台 / 账号` | 必填；候选和后续任务继承，不得由候选改写产品事实 |
| `主体资产池` | 可多选；例如同时选择泰迪和比格。每条候选再明确使用其中一个主体 |
| `母题描述` | 必填，一句话写清“谁、在什么时刻、遇到什么冲突、希望产生什么转变” |
| `商业目标` | 必填，受控值：拉新、种草、转化、复购 |
| `目标时长（秒）` | 必填；必须属于活动内容系统配置允许列表，并通过当前模型目录校验 |
| `特殊要求` | 可选，只写本轮特殊呈现要求，如语言、风格、场景、不露脸或声音偏好；不复制产品硬事实和规则全文 |
| `期望候选数` | 必填，整数 3–12；AI 写入恰好这个数量的合格候选 |
| `收敛方式` | 必填，仅为`人工选择`或`自动 Top N` |
| `自动入选数` | 仅`自动 Top N`使用，整数 1–期望候选数；人工选择时忽略 |
| `流程状态` | `草稿` → `待扩散` → `扩散中` → `候选待确认` → `选择已锁定` → `任务创建中` → `已收敛`；异常统一为`处理失败` |

`创意候选列表`保留为飞书自动反向关联，可在日常视图隐藏。候选表中关联该母题且`候选状态=入选`的记录，是任务创建时的权威选集。

### 3.2 创意候选字段

每条候选必须关联一个母题，并填写`目标人群`、`痛点`、`核心卖点`、`内容形式`、`核心创意`、`钩子`、`叙事结构`、`主要证明动作`和`互动 / CTA`。`钩子`统一承载首帧、首句、声音或动作中的核心停留点，不再拆分多个钩子字段。先写`准入结果`：产品事实、合规、资产可执行和差异化均通过时为`PASS`，否则为`FAIL`并填写`淘汰原因`。通过后填写三项 1–5 分、`评分配置ID`和按活动配置算出的`配置综合评分`；旧`综合评分`仅兼容展示。

`候选状态`只能是`备选`、`入选`或`淘汰`。候选的`落地内容策划任务`为空时不得进入分镜；同一候选只允许关联一条落地任务。

### 3.3 扩散与收敛

1. 人工在`内容母题`填写必填项，设为`待扩散`，再明确要求 AI 扩散。
2. AI 读取母题、产品、可选主体资产和原创规则，内部生成目标数量 2–3 倍的粗方向，经过硬门槛、相似聚类和候选组合配额后，写入恰好指定数量的`创意候选`，全部先标为`备选`。
3. `人工选择`：AI 将母题的`流程状态`改为`候选待确认`并停止。人工可把一条或多条候选标为`候选状态=入选`，包括全部候选；确认完成后将母题设为`选择已锁定`，系统再创建任务。
4. `自动 Top N`：AI 只在`准入结果=PASS`的候选中按`配置综合评分`选择前`自动入选数`条，标为`候选状态=入选`，将母题设为`选择已锁定`并继续创建任务。
5. AI 将每条锁定的入选候选逐字段映射为一条独立的`内容策划任务`，设置`策划模式=原创`、关联产品和`来源创意候选`。任务只继承母题的活动级创作参数。使用母题记录 ID 加候选记录 ID 作为幂等键，回读确认每条关联后再更新状态；一个候选最多对应一条任务。

不得在扩散阶段创建`内容库`记录、生成分镜图、提交 Flow2API Job，或为未入选候选创建任务。

### 3.4 规范字段迁移清单

内容母题当前使用以下简化字段；不再创建审计、快照、运行 ID 或重复选择字段。

| 表 | 规范字段 | 类型/选项 |
| --- | --- | --- |
| `内容母题` | `母题名称`、`母题ID`、`平台 / 账号`、`母题描述`、`特殊要求` | 文本 |
| `内容母题` | `产品` | 单关联到`产品` |
| `内容母题` | `主体资产池` | 多关联到`主体资产库` |
| `内容母题` | `商业目标` | 单选：拉新、种草、转化、复购 |
| `内容母题` | `目标时长（秒）` | 数字；活动配置允许且模型可执行；旧`视频时长`仅兼容历史 |
| `内容母题` | `期望候选数`、`自动入选数` | 数字；候选数 3–12，自动入选数 1–候选数 |
| `内容母题` | `收敛方式` | 单选：人工选择、自动 Top N |
| `内容母题` | `流程状态` | 单选：草稿、待扩散、扩散中、候选待确认、选择已锁定、任务创建中、已收敛、处理失败 |
| `内容母题` | `创意候选列表` | 飞书自动反向关联，可隐藏 |
| `创意候选` | `目标人群`、`痛点`、`核心卖点`、`内容形式`、`核心创意`、`钩子`、`叙事结构`、`主要证明动作`、`互动 / CTA` | 文本；`内容形式`为单选：评论回复、主人直述、挑战记录、POV/反应、实测、教程、ASMR、其他 |
| `创意候选` | `准入结果` | 单选：PASS、FAIL |
| `创意候选` | `淘汰原因` | 多选：产品事实不符、合规风险、资产不可执行、与其他候选同质、其他 |
| `创意候选` | 三项组件分、`评分配置ID`、`配置综合评分` | 数字 1–5、活动配置 ID、按活动权重计算的权威分 |
| `创意候选` | `综合评分` | 历史兼容公式；不得用于自动收敛 |
| `创意候选` | `候选状态` | 单选：备选、入选、淘汰 |
| `创意候选` | `落地内容策划任务` | 单关联到`内容策划任务`；一条候选最多对应一条任务 |

## 4. 内容策划任务

内容策划任务是每次原创或复刻生成的必需任务级方向输入，不是分镜或内容版本。`策划模式`是闭集单选字段，只允许 `原创`、`钩子复刻`、`结构复刻`、`全量复刻` 四个值；空白、旧值`复刻`、空格变体和未知值都视为脏数据，必须停止并报告后清理，不能猜测或自动走未定义分支。创建或更新任务时只能写入这四个规范值。原创与复刻都必须先选择并 fresh-read 恰好一条可用任务；显式复刻时，读取任务的`策划模式`与复刻素材来确定复刻程度；未说“复刻”时默认原创，并选择`策划模式=原创`的任务。任务仍不是产品检索入口：产品事实必须直接从`产品`表读取。每条任务均填写`任务名称`、`策划模式`、`产品`、`平台 / 账号`、`优先级`；`主体资产`在表结构上可选，填写时优先使用；为空时由 agent 从主体资产库自动选择可用匹配记录；`创作要求`可选。任务通过双向字段`内容库版本列表`反向持有所有内容版本，并通过公式字段`内容版本数（自动计数）`统计版本总数；达到版本上限后归档任务和版本，不删除历史记录。旧的`已生成版本数`只保留为历史快照，不再作为轮换事实源。

| 策划模式 | 必填输入 | 允许使用的参考证据 | 原创专用字段 |
| --- | --- | --- | --- |
| 原创 | 产品、平台/账号、原创专用字段；若画面使用跨镜头主体，则必须有可用主体资产（任务已绑定或由 agent 从主体资产库自动选择） | 不使用参考视频 | `目标人群`、`痛点`、`核心卖点`、`钩子`、`叙事节奏`、`证明场景`、`核心创意` |
| 钩子复刻 | 产品；`钩子复用素材`或`爆款视频`/`爆款视频链接` | 钩子复用素材，或爆款视频 `0–3 秒` | 不使用来源视频正文作为原创方向 |
| 结构复刻 | 产品；`爆款视频`或`爆款视频链接` | 全片的阶段时长、叙事功能、证明目标与转场目的 | 不复用任何具体画面、动作、文案或音频 |
| 全量复刻 | 产品；`爆款视频`或`爆款视频链接` | 整条爆款视频 | 不适用 |

自动轮换字段的名称和值均由 Base 架构映射定义。任务的`轮换上限`可显式覆盖；为空时使用活动内容系统配置的默认上限。`已生成版本数`为兼容旧数据保留的历史快照，不得再手工递增。

原创专用字段只在`策划模式=原创`时参与创作；复刻专用字段（`爆款视频`、`爆款视频链接`、`钩子复用素材`）只在三种复刻模式时读取。不得以空白复刻字段代表原创，也不得让原创任务引用复刻素材。`主体资产`可为空；只要脚本、证明场景或分镜使用同一人物/动物/其他可识别主体跨两个以上镜头或跨段连续出现，就从主体资产库自动选择一条可用记录并在内容版本中记录映射；没有主体锚点和身份描述时才停止。若视频超过飞书单文件 20 MB 限制，请填写链接或通过飞书界面上传。

系统必须根据一个选定的内容策划任务制作、调整或热更新内容：用户明确点名任务时读取该任务；用户只提供产品时，先按产品、平台/账号和任务状态选择唯一可用任务，再读取该任务、直接检索的产品记录、主体资产与原创规则，并创建新的内容库版本。不得在正常分镜生成中回写、补全或新建内容策划任务；自动轮换（第 4.1 节）和按第 3.3 节从已入选候选创建原创任务是明确例外。若无法选择唯一可用任务，停止并报告，不得脱离任务自由创作。任务内容的其他修改由人工或用户明确授权的任务维护操作完成。

### 4.1 自动轮换

普通原创生成前，agent 必须 fresh-read 任务生命周期字段、活动内容系统配置和每个双向关联版本。任务上限为空时才使用活动配置默认值，且不得覆盖人工填写的上限。若任务已归档或自动版本总数达到上限：

1. 停止从旧任务继续生成，不删除旧任务或其历史版本。
2. 读取最近内容的标题、钩子、叙事结构、证明场景和创意字段，生成一个有明确差异的新原创方向。
3. 创建一条新的`内容策划任务`，继承产品、平台/账号、优先级、主体资产和长期边界；将`轮换来源任务`指向旧任务，设置`任务状态=活跃`，并继承`轮换上限`。新任务的自动版本数从空的双向版本列表开始计算。
4. 将旧任务更新为`已归档`并写入`归档时间`。新任务写入失败时停止，不创建第二条替代任务。

每创建一个新内容版本，必须将其`内容策划任务`和双向反向字段`任务版本归属`都确认指向同一任务；不得手工递增版本数。历史版本进入旧流程时只将`版本状态`改为`已归档`并填写`归档时间`，不得删除记录。版本总数只用于轮换，不改变内容版本的审核与最终成片门槛。

## 5. 内容版本规则

每个版本是 `内容库` 中独立、可审核的 `content_id`。

- 每个版本均填写 `内容策划任务`、`任务版本归属`、`产品`、`版本号`（如 v1/v2/v3）和`版本状态`。新版本默认`版本状态=活跃`；归档历史版本时只改为`已归档`并写入`归档时间`，不得删除或复用原 record ID。复刻版本的`改编角度`必须等于任务的`策划模式`；原创版本填写`创作模式=原创`、原创创意字段与规则快照。
- 既有脚本、分镜、提示词、附件和审核字段；其中 `画面生成 Prompt` 保存每个分镜板实际提交给图像模型的原文，`视频生成 Prompt` 保存每个配置原始分段实际提交给视频模型的原文。

同一内容策划任务下的版本只能使用其声明的策划模式；爆款视频的镜头逻辑（复刻时）以及产品中的事实和注意事项必须保持一致。若版本改变了装粮路径、出粮/漏食路径、产品结构、审核闸门或视频规格，必须判为无效，不能进入待审核。同一任务的调整或热更新必须新建内容库版本，不能覆盖已审核版本。

### 5.1 重复执行与次数归档

同一条内容库版本可以重复执行，不需要复制新的内容版本，也不需要抽卡状态或独立执行记录表。内容库只维护`已执行次数`和`执行次数上限`：新版本创建时，执行上限继承活动内容系统配置的默认值，人工可以为单条内容调整；每次实际提交一次视频生成任务前，先将已执行次数加一，失败任务同样计数。达到执行次数上限后，把内容库版本的`版本状态`设为`已归档`，不再接受新的执行。

每次成功完成并通过技术验片的执行都直接创建一条`最终成片`记录；通过已有的`最终成片.内容版本`关联即可追溯它属于哪条内容。用户通过比较同一内容版本下的多条最终成片，选择效果最好的一个，不需要额外的抽卡状态字段。

## 6. 最简操作

复刻：新建内容策划任务 → 选择策划模式 → 选择产品 → 按模式上传爆款视频/链接或钩子复用素材 → 可选写创作要求 → 指定生成该任务的 v1、v2 或 v3。

原创：未说“复刻”即自动进入原创 → 先选择并读取一条`策划模式=原创`的可用内容策划任务，再在“产品”表检索产品并读取原创规则；使用任务的原创专用字段（含叙事节奏），但不通过任务的产品关联来定位产品。不读取复刻素材或改写任务。

原创（母题扩散）：新建内容母题并填写必填项 → 明确要求扩散 → AI 内部生成 2–3 倍粗方向并去重 → 写入指定数量创意候选 → 人工选择入选候选或自动 Top N → AI 按入选候选创建一条或多条原创内容策划任务 → 按直接原创流程执行。

系统为指定版本创建或更新内容库记录，再走既有分镜校验和人工审核；“策划模式”本身不等于立即生成成片的授权。

## 7. 最终成片

`最终成片`不是生成队列或中间分段库。用户对一个已通过的`内容库`记录明确下达一次执行指令后，每次完整生成并通过基础技术验片，都创建一条记录；多次执行记录都关联同一个内容版本。

| 字段 | 用途 |
| --- | --- |
| `成片名称`、`成片ID` | 成片显示名与唯一标识 |
| `内容版本` | 必填，关联唯一的来源 `内容库` 版本 |
| `最终视频` | 必填，只上传完整、可发布的最终视频 |
| `视频时长（秒）`、`生成时间` | 实际时长和完成时间 |
| `成片路径或预览链接` | 仅在大文件采用分片上传或外部存储交付时补充 |

不得为失败 Job、单个原始分段或未验片组装件创建记录；成功的重复执行属于独立的最终成片候选。创建最终成片前，必须 fresh-read `内容版本`并确认来源记录存在；无法回读时停止创建，不删除已有视频或把它重新指向其他版本。20 MB 以内可由现有附件上传脚本上传；更大文件使用已验证的分片上传或飞书界面上传，并回读确认附件文件名和 token。
## 四表生命周期与自动归档

`内容母题`、`创意候选`、`内容策划任务`、`内容库`的裂变数据使用同表软归档：保留原记录和关联，只把生命周期状态改为 `已归档`，同时写入 `归档时间`、`归档原因`。`归档保护`勾选时不自动写入。归档规则、字段映射和执行命令见 [lifecycle-archive.md](lifecycle-archive.md)；脚本默认 dry-run，只有明确传入 `--apply` 才写入。产品、主体资产库和最终成片不属于自动归档范围。
